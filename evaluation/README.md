# Evaluation

Three evaluations were run against this project, all with real,
reproducible results.

## 1. Retrieval evaluation

Ran four retrieval configs against a **180-question ground truth set**
(generated by an LLM from 60 real documents — `ground_truth.py`):

| Config | Hit Rate | MRR |
|---|---|---|
| Keyword only | 0.7667 | 0.6561 |
| Vector only | 0.7833 | 0.6603 |
| Hybrid | 0.7944 | 0.6731 |
| **Hybrid + reranking** | 0.7889 | **0.6851** |

**Winner: hybrid + reranking** (highest MRR — it ranks the correct
document highest most consistently). This is the config used in `app.py`.

Reproduce: `python ground_truth.py && python evaluate.py`

## 2. Tool-level evaluation — a real bug found and fixed

`product_test_cases.json` has **24 hand-verified cases**: 12 real
recalled products from actual fetched data, 12 confirmed-safe everyday
products.

**Before** (naive "found in top-5 search results = match"):

| Metric | Value |
|---|---|
| Precision | 0.50 |
| Recall | 1.00 |
| False positives | 12 / 12 negative cases |

Every hand-picked "safe" product (wooden stepstool, ceramic mug set,
etc.) was wrongly flagged as recalled — search always returns *something*
in the top 5, with no relevance threshold.

**After** (added explicit LLM verification: "does this candidate
genuinely match the user's description?" before declaring a match):

| Metric | Value |
|---|---|
| Precision | 1.00 |
| Recall | 0.92 |
| False positives | 0 / 12 negative cases |

The fix, in `tools.py`'s `check_my_product`, eliminated every false
positive at the cost of 1 missed true positive — a clear, evidence-backed
improvement.

## 3. LLM evaluation

Two system prompts compared on 6 questions via LLM-as-judge (scoring
groundedness, clarity, actionability) — `llm_eval.py`:

- **Prompt A** (`INSTRUCTIONS`) — conversational tone
- **Prompt B** (`INSTRUCTIONS_V2_STRUCTURED`) — rigid verdict format

**Result: Prompt A won 4–2.** The app uses Prompt A (already the default).

Reproduce: `python llm_eval.py`
